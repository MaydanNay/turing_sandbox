Техническая документация и ТЗ для Frontend-агента: Turing Sandbox («Бункер» MVP)
Роль: Frontend Developer Agent.
Твоя задача: Разработать клиентскую часть (MVP) игры на социальной дедукции с реалтайм-взаимодействием через WebSockets. Дизайн-код — мрачный корпоративный триллер, интерфейс терминала.
Стек: React, Tailwind CSS, Framer Motion (для VFX и анимаций карточек), Zustand (для стейт-менеджмента комнаты), Vite.

1. Сетевое взаимодействие и Интеграция с Backend
Бэкенд-инфраструктура (FastAPI, Redis, PostgreSQL) уже запущена в Docker.

HTTP REST: http://localhost:8001/api/v1

WebSockets: ws://localhost:8001/ws/room/{room_id}/{client_id}

Особенность сетевого роутинга: Разработка ведется в Google Antigravity IDE внутри окружения WSL. Тебе необходимо настроить Vite-прокси или .env конфиги так, чтобы браузерные фронтенд-агенты корректно маршрутизировали запросы из Windows-дисплея к Linux-подсистеме. Если обычный localhost:8001 падает по таймауту, заложи возможность инъекции явного IP-адреса WSL (например, 172.x.x.x) в переменные окружения VITE_WS_URL и VITE_API_URL.

2. Управление состоянием (Zustand)
Фронтенд должен быть «глупым» терминалом. Вся логика фаз игры диктуется бэкендом. Тебе нужно создать стор, который обновляется по входящим WS-сообщениям:

gameState: INIT, PITCH, CONFLICT, VOTE, RESOLVE.

players: Массив объектов (id, name, role, stats, is_alive, suspicion_score).

chat: Массив сообщений (sender, text, timestamp).

myProfile: Текущая роль и инвентарь локального игрока.

3. Дизайн-система и UI-компоненты
Эстетика: Глубокий черный фон (#0a0a0a), графитовые панели (#171717), акцентный неоновый зеленый для интерфейса терминала (#00ff00) и красный для агрессии/выбывания (#ff003c).

Необходимые компоненты:

Сетка стола (Game Grid): Контейнер, где по кругу или сеткой расположены карточки всех участников комнаты (до 6-8 человек).

Карточка персонажа (Player Card):

Аватар (заглушка), имя, видимые статы (Профессия, Возраст, Здоровье).

Интерактивность: Если на бэкенд уходит голос против этого игрока (увеличивается suspicion_score), карточка должна реагировать через Framer Motion (красная пульсация или CSS-глитч эффект).

Статус: При получении события is_alive: false, карточка должна проиграть жесткую анимацию (выцветание в ЧБ, рассыпание или штамп «ОТКЛОНЕН»).

Терминал чата (Chat Box):

Вывод сообщений в формате [PlayerName_active]: text....

Эффект печатной машинки (typewriter) при получении события «Печатает...» от других игроков/ботов.

Панель управления (Action Bar):

Поле ввода текста (блокируется, если фаза не позволяет говорить).

Кнопки контекстных действий, которые меняются в зависимости от фазы («Опубликовать Питч», «Голосовать за изгнание»).

4. Пайплайн входящих WS-событий (Слушатели)
Настрой роутер сообщений, который будет парсить JSON из сокета:

{"action": "sync_state", "data": {...}} -> Полная перезапись стора.

{"action": "chat", "sender": "ID", "text": "..."} -> Добавление строки в компонент чата.

{"action": "suspicion_up", "target": "ID"} -> Триггер анимации глитча на карточке.

{"action": "typing", "sender": "ID"} -> Показ индикатора активности.

5. Порядок сдачи задачи (MVP)
Инициализировать Vite-проект с Tailwind и Framer Motion.

Настроить WebSocket-провайдер с учетом WSL-роутинга.

Сверстать базовую структуру (Сетка карточек, Чат, Панель действий).

Замокать в UI смену фаз по кнопке, чтобы протестировать анимации без ожидания бэкенд-таймеров.

Связать стор с реальным ws://... эндпоинтом.
